stack and heap memory in javascript
JavaScript handles memory using two primary data structures: the stack and the heap. While the JavaScript engine allocates and clears this memory automatically via Garbage Collection, understanding how they differ is crucial for writing optimized, bug-free code.

Direct Comparison: Stack vs. Heap


Feature	Stack Memory	Heap Memory
Allocation Type	Static memory allocation (fixed size at compile/execution time)	Dynamic memory allocation (size can change at runtime)
Data Stored	Primitives (string, number, boolean, null, undefined, symbol, bigint) and references (pointers to the heap)	Reference types (objects, arrays, functions, maps, sets)
Structure	Unidirectional, orderly LIFO (Last In, First Out)	Unstructured, free-form large pool of memory
Speed	Extremely fast access	Slower access (due to lookup and pointer references)
Management	Managed automatically via execution context / function scopes	Managed automatically by the engine's Garbage Collector


1. Stack Memory: The Organized Tracker

The Stack is responsible for keeping track of the order of execution (via the Call Stack) and storing short-lived data. Because primitives have a fixed size, the JavaScript engine knows exactly how much space to reserve ahead of time.
When you copy a primitive value stored in the stack, JavaScript creates a completely independent copy (Pass by Value):
javascript
let a = 10; 
let b = a; // A brand new space in the stack is created for 'b'
b = 20;

console.log(a); // 10 (unaffected)
console.log(b); // 20
Use code with caution.

2. Heap Memory: The Flexible Warehouse

The Heap is a massive, unstructured memory space used for objects whose sizes can grow or change. Because the size of an object or array is unpredictable, JavaScript cannot store it directly in the stack.
Instead, the actual object is placed in the Heap, and a hexadecimal memory address (pointer) is created in the Stack to point to it.
When you copy a reference type, JavaScript only copies the pointer, not the actual data (Pass by Reference):
javascript
const user = { name: "Alice" }; // Object goes to Heap; reference address goes to Stack
const admin = user;             // Copies the reference address, NOT the object

admin.name = "Bob";             // Modifying 'admin' changes the shared Heap object

console.log(user.name);         // "Bob" (Both variables point to the exact same memory location)
Use code with caution.

Common Limitations & Pitfalls

• Stack Overflow: The stack has a strict size limit. If a function calls itself indefinitely (infinite recursion) without resolving, the stack overflows and crashes the program.
• Memory Leaks: If a variable in the stack holds a reference to a giant object in the heap, that object cannot be collected by the garbage collector. If you inadvertently keep references alive (e.g., active global variables or unremoved event listeners), it results in memory leaks.

	• Yeh fixed size ka hota hai aur ekdum fast kaam karta hai.
• Heap:
	• Yahan bade aur dynamic data types (Objects, Arrays, Functions) save hote hain.
	• Yeh bada store room hai, jo thoda unstructured aur stack se thoda slow hota hai.

2. Code Behavior (Copy Kaise Hota Hai?)

• Pass by Value (Stack): Primitives ko copy karne par bilkul independent, naya variable banta hai. Ek ko badlo, dusre par asar nahi padta.
• Pass by Reference (Heap): Objects/Arrays ko copy karne par sirf unka address (pointer) copy hota hai. Ek ko badlo, toh asli data badal jata hai (Bug alert! ⚠️).
	• Solution: Hamesha Spread Operator (...) ya .map() ka use karein naya object banane ke liye.

3. Browser Hang aur Errors (Heap Problems)

• Aw, Snap! / Out of Memory Error: Agar infinite loop chala kar Heap me bina ruke data bharte gaye, toh computer ki RAM full ho jayegi aur browser crash ho jayega.
• Browser Lag / Hang: Jab Heap me bohot saara faltu data jama ho jata hai, toh JS ka Garbage Collector use saaf karne aata hai. Safai karte waqt browser kuch milliseconds ke liye freeze (atak) jata hai.

4. As a Dev Aapko Kya Karna Hai?

• Aapko manually memory allocate ya delete nahi karni (JS auto karta hai).
• Lekin coding karte waqt infinite loops se bachna hai aur Objects/Arrays ko safe tarike se copy karna hai taaki bugs na aayein.

1. Scope Kya Hai? (Aapki Limit/Boundary)

Scope ka matlab hai Aapka variable aapke code me kahan tak zinda hai. Agar aap kisi variable ko uski boundary ke bahar use karne ki koshish karoge, toh JS error de dega: ReferenceError: variable is not defined.
JavaScript me main do tarah ke scope hote hain:
• Global Scope: Jo variable kisi function ke bahar khule me likha ho. Ise poore code me kahin se bhi use kiya ja sakta hai.
• Local / Function Scope: Jo variable kisi function ke andar { } ke beech me likha ho. Ise sirf usi function ke andar use kar sakte hain, bahar se access nahi kar sakte.

2. Lexical Environment Kya Hai? (Upar Dekhne Ka Rule)

"Lexical" ka simple matlab hota hai "Kahan likha hua hai".
Jab aap kisi function ke andar koi variable dhoondte ho aur wo wahan nahi milta, toh JavaScript ka engine apne parent (apne se upar wale) area me jaakar us variable ko dhoondta hai. Is poore system ko Lexical Environment kehte hain.

javascript

  console.log(localSaman);  // Yeh chal jayega? HAAN! (Ghar ka saman hai)
}

ghar(); // Function chalaya

console.log(localSaman); // ❌ ERROR! (Bahar khada aadmi ghar ke andar ka saman nahi dekh sakta)
Use code with caution.

4. 📊 Scope Chain Kaise Kaam Karti Hai? (The Ladder)

Maan lijiye ek ke andar ek function likha hai (Nested Functions). Tab JS variable ko niche se upar ki taraf ek sidi (chain) ki tarah dhoondta hai:

    let betaKaKhilona = "Beta ka khilona";

    console.log(betaKaKhilona); // Sahi hai (Khud ka saman hai)
    console.log(papaKiCar);     // Sahi hai (Papa se le sakta hai - Upar dekha)

🎯 String Reverse Karne Ki 3-Step Trick

Maan lijiye aapka naam "Rahul" hai aur aapko ise "luhaR" banana hai:
javascript
let name = "Rahul";

// Step 1: .split("") use karke string ko tod kar Array banao

// Output: ["R", "a", "h", "u", "l"]

// Step 2: Array ke built-in .reverse() method se list ko ulta karo
let reversedArray = arrayName.reverse(); 
// Output: ["l", "u", "h", "a", "R"]

// Step 3: .join("") use karke array ko wapas jod kar String banao
let finalResult = reversedArray.join(""); 
// Output: "luhaR"

console.log(finalResult); // "luhaR"
Use code with caution.
