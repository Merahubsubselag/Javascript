1. CODE LIKHNE SE PEHLE SOCHEIN (THINK BEFORE YOU CODE)
----------------------------------------------------------------
- Seedha keyboard par typing shuru na karein. Pehle ek rough paper 
  ya comments mein steps likhein ki input kya hoga, logic kya 
  lagega, aur output kya aayega.
- Agar aap problem ko plain Hindi/English mein explain nahi kar 
  pa rahe, toh uska code likhna mushkil hoga.

2. SMALL & PURE FUNCTIONS BANAYEIN
----------------------------------------------------------------
- Pure Function: Ek aisa function jo bahar ke kisi variable ko change 
  na kare, aur same input dene par hamesha same output de.
- Isse bugs bahut kam aate hain aur code test karna aasan ho jata hai.

3. EARLY RETURN PATTERN USE KAREIN (NESTED IF-ELSE SE BACHEIN)
----------------------------------------------------------------
- Code ko andar-hi-andar (nested) le jaane ke bajay galat conditions 
  ko pehle hi 'return' karke bahar nikal dein.

  [BAD - Nested]                  [GOOD - Early Return]
  function check(user) {          function check(user) {
    if (user) {                     if (!user) return;
      if (user.isActive) {          if (!user.isActive) return;
        // main logic               // main logic (clean & flat)
      }                           }
    }
  }

4. MAGIC NUMBERS AUR STRINGS SE BACHEIN
----------------------------------------------------------------
- Code ke beech mein achanak koi number ya string na dalein jiska 
  matlab kisi ko samajh na aaye. Unhein ek uppercase constant mein rakhein.

  [BAD]                           [GOOD]
  if (age >= 18) { ... }          const MINIMUM_VOTING_AGE = 18;
                                  if (age >= MINIMUM_VOTING_AGE) { ... }

5. STRICT EQUALITY (===) KA HI USE KAREIN
----------------------------------------------------------------
- Hamesha '===' aur '!==' ka use karein, '==' ka nahi.
- '==' data type check nahi karta (jaise 0 == false true hota hai), 
  jisse ajeeb bugs aate hain jo pakad mein nahi aate.

6. CONST BY DEFAULT, LET WHEN NEEDED
----------------------------------------------------------------
- Har variable ko pehle 'const' se banayein.
- Sirf tabhi 'let' use karein jab aapko pata ho ki iski value aage 
  badalne wali hai (jaise loop counter). 'var' ko bilkul bhool jayein.

7. CONSOLE.LOG KE AAGE BADHEIN (PRO DEBUGGING)
----------------------------------------------------------------
- Badi objects ya arrays ko dekhne ke liye console.table(data) use karein, 
  yeh data ko clean table format mein dikhata hai.
- Har line par console.log lagane ke bajay DevTools mein 'debugger;' 
  likhein ya Breakpoint lagayein.

8. COMMENTS 'KYUN' BATAYEIN, 'KYA' NAHI
----------------------------------------------------------------
- Aapka code khud batana chahiye ki woh 'kya' kar raha hai (achhe naam se).
- Comments sirf yeh batane ke liye likhein ki aapne yeh logic 'kyun' 
  chuna (e.g., // API rate limit se bachne ke liye 500ms delay lagaya hai).

9. CODE KO REFACTOR KARNA NA BHOOLEIN
----------------------------------------------------------------
- Jab aapka code chal jaye, toh 5 minute ruk kar use dobara padhein.
- Dekhein kya koi duplicate code hataya ja sakta hai? Kya koi variable 
  ka naam aur behtar ho sakta hai?

10. ERROR KO KABHI IGNORE NA KAREIN
----------------------------------------------------------------
- Khali catch block (catch (err) {}) kabhi na chhodein. Error ko 
  console.error(err) mein log karein ya user ko sahi message dikhayein.

****************************** "Example of bad code" *************************


var u = [
  { n: "rahul", a: 1 },
  { n: "priya", a: 0 },
  { n: "amit", a: 1 }
];

function get() {
  var res = [];
  for (var i = 0; i < u.length; i++) {
    if (u[i].a == 1) {
      res.push(u[i].n.toUpperCase());
    }
  }
  return res;
}
console.log(get());


****************************** "Notic point:" *************************

Bad Naming: u, n, a, get, res
Memory Issue (var): var
Hardcoded Data: Function bahar ke global array u par depend hai, 
isse aap is function ko kisi doosre array ke liye reuse nahi kar sakte.
No Error Handling: Agar u khaali ho, ya null aa jaye.



****************************** "Pro Developer Code (Clean, Fast, aur Safe):" *************************

6 factors (Readability, Speed, Memory, Error Handling, Reusability)

const usersList = [
  { name: "rahul", isActive: true },
  { name: "priya", isActive: false },
  { name: "amit", isActive: true }
];

function getActiveUserNames(users) {
  // 1. Edge Case & Error Handling (Code crash hone se bachana)
  if (!Array.isArray(users) || users.length === 0) {
    return [];
  }

  // 2. Speed & Memory Optimization (Ek hi loop mein kaam khatam)
  const activeNames = [];
  
  for (const user of users) {
    // Check kiya ki user active hai aur uska name string hai
    if (user?.isActive && typeof user.name === "string") {
      activeNames.push(user.name.toUpperCase());
    }
  }

  return activeNames;
}

console.log(getActiveUserNames(usersList)); // Output: ["RAHUL", "AMIT"]


****************************** "Pro Developer Tips:" *************************

• Readability: usersList, isActive, aur getActiveUserNames padhte hi samajh aa raha hai ki code kya kar raha hai.
• Reusability: Ab aap getActiveUserNames() mein koi bhi doosra array pass kar sakte hain, yeh har jagah kaam karega.
• Speed (Single Pass): Agar hum .filter().map() lagate toh array par 2 baar loop chalta. 
Ek single for...of loop lagane se kaam 1 hi pass mein fast ho gaya.
• Memory Safety: const ka use kiya hai, jisse function khatam hote hi activeNames aur user memory (RAM)
 se turant clean ho jayenge.
• Crash-Proof (Edge Cases): Agar koi getActiveUserNames(null) ya { name: null, isActive: true } bhi bhej de,
 toh Array.isArray aur optional chaining (user?.isActive) ki wajah se code kabhi error nahi dega.
